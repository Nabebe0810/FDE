# 要件ヒアリング（AIを使わない汎用要件定義ツール）

非エンジニアが普段の言葉で答えるだけで、事業要求から機能・非機能・データ・権限・技術選定条件までを構造化するヒアリングツールです。
**ヒアリング中に生成AIや外部APIは一切使いません。** 質問の選択、分岐、深掘り、矛盾の検出、要件への変換、終了の判定は、すべて質問DB・条件式・ルールエンジン・状態管理（回答ログの再生）で行います。

## 結論（いまできること）

| 項目 | 状態 |
|---|---|
| 回答画面 | 1画面1問。スワイプ・タップ・キーボードで操作。入力形式は14種（2択＋第3の操作、ボタン、ドロップダウン、目盛りスライダー、程度スライダー、複数選択、3方向のカード仕分け、10点配分、並べ替え、立場×できることの表、数値、年月、テキスト、時系列の手順） |
| 質問DB | 151問（受付10・業務58・システム74・汎用の深掘り9）。1回のヒアリングで出すのはその一部（シミュレーションでは142問中67〜86問） |
| 所要時間 | シミュレーションの推定は22〜30分（6シナリオ）。**推定値で実測ではない** |
| 出力 | 要件定義書（Markdown）、スプレッドシートに貼るTSV（要件・未決定事項・回答と計測ログ）、回答ファイル（JSON） |
| 検査 | `npm test` で18件（DB検査・決定論・分岐・矛盾・訂正・確認・時間上限など）。実ブラウザの通し操作（`node tools/e2e.js`）でエラー0・外部通信0・横はみ出し0 |
| 費用・送信 | 追加費用なし。データは端末内（ブラウザ保存）と書き出したファイルだけ。外部へ送信しない |

## 使い方

1. `dist/fde-hearing.html` をブラウザで開きます（1ファイルで完結。サーバー不要）。開発中は `index.html` でも動きます。
2. 案件名と回答者の立場（経営者／管理者／現場／IT担当）を選んで「始める」。
3. 終わったら「担当者に渡すファイルを保存」。FDE はそのファイルを開き、右上の「FDE」から要件定義書・TSV を書き出します。
4. 別の立場の人に続きを答えてもらうときは、FDE 画面「回答・計測」から回答者を追加します（回答者間の食い違いは対置型の質問で確かめます）。

```bash
npm run build
```

```bash
npm test
```

```bash
npm run simulate
```

```bash
npm run analyze -- <回答ファイルを集めたフォルダ>
```

## しくみ（10ステップ）

| ステップ | 実装 |
|---|---|
| 1 相談内容の理解 | 受付の質問（固定順）。原文は書き換えず保存 |
| 2 事実・推測の分類 | 自由記述の直後に、本人が「見た・数えた／聞いた／推測／希望」を選ぶ（AIで推定しない） |
| 3 論点候補の抽出 | 案件の型からの規則＋論点カードの仕分け（関係ある／ない／わからない） |
| 4 競合仮説の設定 | 原因の7仮説・解決のかたち4仮説（「作らない」案を含む）。各仮説に反証条件と判別質問 |
| 5 質問の選択 | 矛盾確認 → 追加質問 → 必須 → スコア順。スコア＝不確実性・判断への影響・重要度・後続への影響・分岐・会話の順 − 回答負荷 |
| 6 平易な一問 | 事前に平易文で作成し、ビルド時に専門用語・論点の並列・疑問符の数・前提の混入を検査 |
| 7 回答の分析 | 選択式は確実に分類。自由記述は形式だけを判定（抽象語・手段語・推量語・数字の有無など） |
| 8 追加質問 | 抽象的→直近の一件、手段だけ→元の困りごと、根拠なし→根拠の種類、二手目まで。三手目は人に回す |
| 9 要件への構造化 | 72の変換ルールで BR／FR／NFR／ENT／REL／PERM／INT／CON／AC／ADR などへ。**推定はすべて「未確認」** |
| 10 顧客確認 | 重要な要件を平易な文でカードにし「合っている／ちがう／保留」。「ちがう」は外れた部分だけを聞き直す |

判定は「仕様確定／条件付き／未確定」の3段（R01〜R09）。顧客確認と FDE の自由記述レビューが済むまで「仕様確定」になりません。

## フォルダ

| パス | 中身 |
|---|---|
| `data/questions/*.json` | 質問DB（正本）。書き方は `docs/QUESTION_SCHEMA.md` |
| `data/slots.json`・`data/values.json` | 回答の受け皿（項目辞書）と選択肢の正規の値 |
| `data/rules/*.json` | 論点・仮説・矛盾・分岐・深掘り・要件変換・技術選定・語彙辞書 |
| `data/params.json` | 重み・閾値・時間（**初期設計値。実測で調整する**） |
| `src/engine/*.js` | エンジン（ブラウザと Node の両方で動く） |
| `src/ui/*` | 回答画面と FDE 画面 |
| `tools/` | ビルド・束ね・シミュレーション・実測集計・CSV書き出し・E2E |
| `docs/00_資料分析.md` | 3資料と実案件の精読結果（使える／一般化できない／足りない）、標準手法との統合、設計要素の出典表 |
| `docs/01_設計書.md` | 10ステップの入力・判断ルール・出力・遷移・エラー処理、選択アルゴリズム、データモデル、基盤の比較 |

## 制限（AIなしで保証できないこと）

- 自由記述の意味・言い換え・自由文どうしの矛盾は判定しません。原文を残し、FDE 画面「人間レビュー」に回します。
- 矛盾の自動検出は、構造化された項目どうし（11規則）と回答者間の食い違いだけです。
- 重み・閾値・回答秒数の推定・技術候補の点数は初期設計値です。実測ログ（`tools/analyze-logs.js`）で見直してください。
- 技術選定の上限・料金は前回成果物で 2026-11-13 に確認した値で、このリポジトリでは再確認していません。採用前に出典で確認してください。
- 法令・セキュリティ・費用の結論は出しません（論点を出すところまで）。
