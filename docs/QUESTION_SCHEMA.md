# 質問DBの書き方（スキーマと執筆ルール）

質問は `data/questions/*.json`（配列）に書く。ビルド（`node tools/build.js`）で1つにまとめ、`node --test` の検査を通らないものは使えない。

## 1. 列（属性）

| 属性 | 必須 | 意味 |
|---|---|---|
| `id` | ○ | `Q-<区分3文字>-<3桁>`。区分：INT受付 VIS思い PRB困りごと KPI成果 FLW流れ RUL決まり DAT情報 ROL使う人 OUT画面出力 LNK連携 NFR規模安全 CON予算体制 MIG移行 TOC利用者体験 AIF AI機能 ACC優先完成 CHG修正 |
| `phase` | ○ | `data/params.json` の `phaseOrder` のどれか（例 `04_仕事の流れ`） |
| `step` | ○ | 対話エンジンの10ステップ番号（1〜10。通常の質問は5〜9、深掘りは8） |
| `topic` | ○ | 論点ID（`data/rules/topics.json`）。論点が無効なら出題されない |
| `persona` | ○ | `"全員"` または配列（`経営者`／`管理者`／`現場`／`IT担当`）。対象外の人には出さない |
| `text` | ○ | 質問文。**平易な日本語・一問一論点・疑問符は1つ・60字以内**。専門用語禁止（下記） |
| `help` | | 補足・例。具体例を1つ入れると回答負荷が下がる |
| `intent` | ○ | **何を判定するための質問か** |
| `decides` | ○ | **回答によって何が決まるか**（配列・空は不可） |
| `technique` | ○ | 深掘り手法：`具体要求型`／`対置型`／`仮置き型`／`選択の問い`／`運用の問い`／`契約の問い`／`時点の分離`／`時系列追跡`／`数量のケタ`／`採否テスト` |
| `slot` | ○ | 回答を入れる項目（`data/slots.json`）。エンティティ別は `DAT.{param}.count` と書き `forEach: "DAT.things"` を付ける |
| `input` | ○ | 回答形式（下の表） |
| `trigger` | | 発動条件（条件式。`src/engine/cond.js` 冒頭の書式） |
| `skipIf` | | 出さない条件 |
| `presupposes` | | この質問が前提にしている項目。**その項目が回答済みでないと出題しない**（前提の混入を防ぐ） |
| `mandatory` | | `true` または条件式。必須確認項目 |
| `importance` | ○ | 要件定義上の重要度 1〜5 |
| `costSec` | | 推定回答秒数（省略時は形式ごとの既定値）。実測で更新する |
| `followups` | | `[{when, ask, why}]`。`when` には `{"det":"abstract"}`（直前の自由記述の判定）やスロット条件が使える。`ask` 先は `queuedOnly: true` の質問か汎用深掘り |
| `queuedOnly` | | true＝追加質問としてだけ出る（単独では選ばれない） |
| `deepdive` | | 自由記述の形式判定で汎用深掘りを許す判定名：`solutionOnly`／`abstract`／`needsEvidence`／`speculative` |
| `epistemic` | | true＝回答後に「事実／伝聞／推測／希望」を本人に分けてもらう |
| `patterns` | | 想定される回答パターン（文書用） |
| `hypothesis` | | 確認したい仮説 |
| `falsifier` | | 反証条件（どんな回答なら仮説が外れるか） |
| `outputs` | ○ | 変換先の要件項目（`BR`、`FR`、`NFR`、`ENT`、`ATTR`、`REL`、`ROLE`、`PERM`、`BP`、`RULE`、`INT`、`CON`、`AC`、`ADR` やスロット名） |
| `dedupe` | | 重複グループ名。同じグループは1問だけ出る |
| `sources` | ○ | 根拠。`A:<シート名>`／`B:§<章>`／`C:VS<n>` or `C:原則<n>`／`D:§<n>`（実案件分析）／`zip:<旧質問ID>`／`STD:<標準名>` |

## 2. 回答形式（`input.type`）— 2択に限定しない

| type | 画面 | 使いどころ | 値 |
|---|---|---|---|
| `yesno` | 左右スワイプ＋**上スワイプ＝どちらとも言えない** | 事実の有無。排他にならない問いだけ | `true`/`false`（どちらとも言えない＝dontknow） |
| `single` | 縦に並ぶボタン（7個以下） | 互いに排他な選択肢 | 値文字列 |
| `select` | ドロップダウン（ピッカー） | 選択肢が8個以上 | 値文字列 |
| `slider` | 目盛り付きスライダー | **順序のある選択肢**（人数・件数・頻度・金額のケタ）。`options` を小さい順に | 値文字列 |
| `scale` | 5段階スライダー | 程度（重要度・困り度）。`options` 5つ | 値文字列 |
| `multi` | チップの複数選択 | 当てはまるものすべて | 配列 |
| `cards` | カードを3方向に仕分け（当てはまる／ちがう／わからない） | 候補の一次仕分け（論点・原因仮説・扱う情報） | `{yes:[],no:[],unknown:[]}` |
| `points` | 10点を配分するスライダー群 | 優先度の相対比較（二択にしない） | `{値: 点}` |
| `rank` | タップ順に並べる | 上位の順番が必要なとき | 配列（順） |
| `matrix` | 行×列のタップ表（行は `rowsFrom` スロット） | 立場×できること（見る／変える／なし）など | `{行: 列}` |
| `number` | 数値＋単位＋よく使う値のボタン | 正確な数が言えるとき | 数値 |
| `month` | 年月ピッカー | 期限 | `YYYY-MM` |
| `text` / `longtext` | 1行／複数行 | 原文が必要なときだけ（自由記述は意味判定しない） | 文字列 |
| `steps` | 手順を1行ずつ足す（時系列） | 実際の一件の流れ | 配列 |

- 選択肢は `{"v": 正規の値, "label": 表示, "set": {他スロット: 値}, "flags": [...], "ask": 追加質問ID}`。`v` は **`data/values.json` の値だけ**。
- すべての質問に「わからない／後で確認／該当しない」が自動で付く（書かなくてよい）。
- 排他的な二択（「AですかBですか」で両方・どちらでもないがあり得る）は禁止。`single` に「両方」「どちらでもない」を入れるか `points` を使う。

## 3. 執筆ルール（検査で落ちるもの）

1. 一問一論点：疑問符は1つ。「〜と〜について」「また」「および」で論点を並べない。
2. 専門用語禁止：要件、仕様、KPI、ROI、API、DB、データベース、エンティティ、属性、権限、認証、非機能、ワークフロー、ステータス、マスタ、UI、UX、MVP、スコープ、ステークホルダー、トランザクション、バッチ、インテグレーション。
3. 前提の混入禁止：相手がまだ言っていないこと（「〜が問題になっていると思いますが」「〜はもう決まっていますね」）を文に入れない。前提にするスロットは `presupposes` に書く。
4. 解決策を先に出さない：受付〜困りごと〜成果の段階の質問文に、手段（アプリ・自動化・AI など）を入れない。
5. `decides` が空の質問は登録しない（判断が変わらない質問は聞かない）。
6. 数や量は自由記述でなく `slider`（ケタの目盛り）で聞く。正確な値が必要なときだけ `number`。
